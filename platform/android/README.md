# TransitFlow — приложение за myPOS терминал

Приложението за гише и за автобус. Носи сайта вътре в себе си и **сам управлява
четеца** на терминала.

## Защо не е просто браузър

myPOS терминалът не подава сканираната карта на страницата, както прави
телефонът — никакво NFC събитие не пристига. Приложението кара четеца само,
през SDK-то на myPOS: свързва се, отваря го и го чете в цикъл.

Две неща тук не са очевидни и **не трябва да се пипат**:

**`MyPOSAPI.registerPOSInfo()`** в `MainActivity`. Терминалът държи четеца
заключен, докато приложение не се представи през SDK-то. Без това извикване
четецът просто не отговаря и нищо не обяснява защо.

**Екранът се затъмнява, но не заспива.** Сканирането спира, когато машината
заспи. Затова приложението слага черен слой отгоре и сваля подсветката до
минимум — изглежда изгасен, но е буден. Някои терминали не приемат яркост нула,
затова има и слой, не само яркост.

## Какво е нужно

* Android Studio (носи си Java 21 — Capacitor 8 иска точно нея)
* Android SDK, platform 36
* Терминалът, включен през USB с включено USB debugging

## Отваряне

В Android Studio: **Open** → изберете папката `platform/android`.

Ако Gradle се оплаче, че не намира SDK-то, направете `local.properties` с път
без обратни наклонени черти:

```
sdk.dir=C:/Users/<име>/AppData/Local/Android/Sdk
```

Файлът трябва да е **без BOM** — иначе ключът не се разчита и грешката говори за
липсващо SDK, което подвежда.

## Правене на подписано приложение

Терминалът иска подписан APK. Ключът е **нов** и няма нищо общо със стария на
DaryCard.

1. **Build → Generate Signed App Bundle / APK → APK**
2. **Create new…** — попълва се и се запазва `.jks` файлът
3. Пазете `.jks` файла и паролите. Без тях **не може да се издаде обновление** на
   вече инсталирано приложение — Android отказва APK, подписан с друг ключ.
4. Build variant: **release**

Готовият файл излиза в `app/build/outputs/apk/release/`.

Ключът **не влиза в хранилището**. Дръжте го отделно и на резервно място.

## Слагане на терминала

```
adb install -r app/build/outputs/apk/release/app-release.apk
```

или копирайте APK-то на терминала и го отворете оттам.

## Какво да проверите при първо пускане

С включен терминал през USB:

```
adb logcat -s TransitFlow
```

Трябва да излязат, в този ред:

```
Terminal unlocked      ← SDK-то е отключило хардуера
Reader bound           ← четецът е свързан
Reader loop started    ← чака карта
```

Ако **`Terminal unlocked` не се появи**, приложението не е разпознато от
терминала. Тогава четецът няма да работи, каквото и друго да е наред.

## Обновяване след промяна в сайта

Сайтът е **вътре** в приложението, не се тегли. Промяна в него стига до
терминалите чак след ново приложение:

```
cd platform
npm run build
npx cap sync android
```

после ново подписано APK от Android Studio.

Това е цената на решението сайтът да се носи вътре — терминал без интернет за
малко продължава да работи. Така е и при DaryCard.

## Файлове, които вършат работата

| файл | какво прави |
|---|---|
| `MainActivity.java` | отключва терминала, гаси екрана без да заспива |
| `TransitFlowNfcPlugin.java` | чете картата — сериен номер и адрес — и ги подава на страницата |
| `AndroidManifest.xml` | вижда приложението на myPOS, поема линковете на картите |
| `app/build.gradle` | дърпа `com.mypos:mypossmartsdk` |

Страницата слуша събитието като плъгин на име **`TransitFlowScanner`**
(`src/services/MyPosSmartSdk.ts`). Ако името се смени тук, трябва да се смени и
там — иначе страницата не намира четец и нищо не се случва.
